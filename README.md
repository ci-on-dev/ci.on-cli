# ci.on-cli

**CI.ON** is an open-source CLI tool for unit testing CI/CD pipelines.

It allows you to:

* Run local pipelines for GitLab, GitHub Actions, or Azure DevOps without needing a real CI server.
* Create **declarative tests** for pipelines, with asserts for jobs, steps, statuses, and variables.
* Generate execution reports and coverage for pipelines.
* Execute pipelines in **dry-run** mode or within **Docker**, keeping your repository clean.

---

## 🔹 Purpose

CI/CD pipelines often contain complex logic, dependencies, and variables that are difficult to test before pushing to GitLab/GitHub/DevOps.

**ci.on-cli** solves this by allowing you to:

* Test pipelines locally in an automated way.
* Verify that jobs and steps work as expected.
* Ensure environment variables and `.env` files are created correctly.
* Maintain pipeline test coverage and prevent regressions.

## ⚡ Installation

### Using Go

```bash
go install github.com/ci-on-dev/ci.on-cli/cmd/ci.on@latest
```

### Using Homebrew (recommended for macOS)

```bash
brew install gitlab-ci-local   # depends on gitlab-ci-local installed via brew
```

> **Note:** `ci.on-cli` internally uses `gitlab-ci-local` to execute GitLab pipelines.

## 🏃 Commands

### Test a pipeline suite

```bash
ci.on test -t <path_to_test_yaml>
```

Example:

```bash
ci.on test -t examples/gitlab/create_global_env.test.gitlab-ci.yml
```

* Runs the test pipeline, generates temporary variables and artifacts inside `tmp/`.
* Checks the asserts defined in the test YAML.
* Returns exit code `0` if all asserts pass, `1` if any fail.

### Initialize local environment

```bash
ci.on init
```

* Installs necessary dependencies (e.g., `gitlab-ci-local` via Homebrew).
* Creates temporary directories for pipeline execution.

### Dry-run a pipeline

```bash
ci.on run -t <test_yaml> --dry-run
```

* Simulates pipeline execution without actually running commands.
* Useful for validating structure, asserts, and coverage.

## 📂 Folder Structure

```
ci.on-cli/
├─ cmd/ci.on/             # main CLI command
├─ internal/
│  ├─ runner/             # implementations of local or Docker runner
│  ├─ providers/          # workflow parser (GitLab, GitHub Actions, Azure)
│  └─ assert/             # logic for asserts and results
├─ examples/              # example pipelines and tests
└─ tmp/                   # temporary directory for test execution
```

## 🔧 Example GitLab Test

**create\_global\_env.test.gitlab-ci.yml**

```yaml
variables:
  ACTION: test
  ZONE: zone-01
  ENVIRONMENT_CODE: test

stages:
  - init

include:
  - "examples/gitlab/create_global_env.gitlab-ci.yml"

asserts:
  - name: "Check env creation"
    expect:
      job: create_global_env
      step: script
      step_status: success
```

* The wrapper YAML is automatically generated by `ci.on-cli` inside `tmp/`.
* Ensures `global.env` and variables are correct.
